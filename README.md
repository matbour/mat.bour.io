# mat.bour.io

My personal blog. Markdown files, built by [Astro](https://astro.build) into a static site, served by Caddy, deployed with Coolify to an Orange Pi at home.

## Writing

```sh
bun install
bun run dev        # http://localhost:4321, drafts included
```

Posts live in `src/content/posts/<slug>.md`. The filename becomes the URL (`/posts/<slug>/`).

```markdown
---
title: My post
description: One sentence, used in lists, RSS and link previews.
date: 2026-11-07
category: tech # tech | work | side-projects | tennis | life
tags: [astro, docker]
draft: true # visible in dev only; set to false to publish
---
```

Images go next to the post or in `public/`. Projects are in `src/content/projects/`, the about page is `src/pages/about.md`, and your name, links and categories are in `src/site.config.ts`.

`src/content/posts/markdown-style-guide.md` is a permanent draft that shows every element, handy when changing styles.

## Checking

```sh
bun fmt            # format everything (Prettier style; .astro files go through prettier-plugin-astro)
bun run check      # types and content schema
bun run build      # production build into dist/ (drafts excluded)
bun run preview
```

Git hooks are managed by [Lefthook](https://lefthook.dev) and installed by `bun install`:

- **pre-commit** formats the staged files with `bun fmt --staged`.
- **pre-push** runs `bun run check`.

Skip them once with `LEFTHOOK=0 git commit …`.

## Deploying with Coolify

1. Push this repository to GitHub.
2. In Coolify: **New resource → Public/Private repository**, pick the repo and branch `main`.
3. Build pack: **Dockerfile**. Port: **80**.
4. Domain: `https://mat.bour.io`.
5. Enable automatic deployment on push (webhook or GitHub App).
6. Optional analytics: add `PUBLIC_UMAMI_SRC` and `PUBLIC_UMAMI_WEBSITE_ID` as **build variables** (see `.env.example`).

### Cloudflare Tunnel

The site is reached through a Cloudflare Tunnel, so Cloudflare handles HTTPS and the Pi has no open ports.

- In the tunnel, add a public hostname `mat.bour.io` with service `http://localhost:80` (Coolify's proxy). Use `http://127.0.0.1:80` if `localhost` resolves to IPv6.
- In Coolify, keep the domain as `https://mat.bour.io` but turn **Redirect HTTP to HTTPS** off for this resource. The tunnel talks to Coolify over plain HTTP, so leaving it on causes a redirect loop (`ERR_TOO_MANY_REDIRECTS`).

Caddy (`Caddyfile`) serves the files inside the container on port 80 with compression and cache headers. It doesn't deal with certificates.

## Container image (CI)

`.github/workflows/image.yml` builds a `linux/arm64` image and publishes it to `ghcr.io/matbour/mat.bour.io`:

1. **Build** the image and **scan** it with [Trivy](https://trivy.dev). All findings go to the repo's Security tab. The run fails on a CRITICAL vulnerability that has a fix. To accept a specific CVE, add its ID to `.trivyignore`.
2. **Push** it as `latest` and `sha-<commit>` (only on `main`; pull requests stop after the scan).
3. **Sign** it with [cosign](https://docs.sigstore.dev), keyless: the signature is tied to this repo's workflow through GitHub's OIDC token and recorded in Sigstore's public transparency log.
4. **Attach a CycloneDX SBOM**, generated by Trivy and signed the same way.

It also runs every Monday so the image picks up patched base images and gets checked against new CVEs. Dependabot keeps the pinned actions and base images current.

Verify an image:

```sh
IMAGE=ghcr.io/matbour/mat.bour.io:latest
ID='https://github.com/matbour/mat.bour.io/.github/workflows/image.yml@refs/heads/main'
ISSUER=https://token.actions.githubusercontent.com

cosign verify "$IMAGE" --certificate-identity "$ID" --certificate-oidc-issuer "$ISSUER"

# Verify the SBOM and print it
cosign verify-attestation "$IMAGE" --type cyclonedx \
  --certificate-identity "$ID" --certificate-oidc-issuer "$ISSUER" \
  | jq -r '.payload | @base64d | fromjson | .predicate' | head
```

Rescan the published SBOM without pulling the image: `trivy sbom sbom.cdx.json` (download the file from the workflow run).

To deploy that image rather than building on the Pi, set the Coolify resource to **Docker Image** `ghcr.io/matbour/mat.bour.io:latest`. GHCR packages start out private: make the package public, or give Coolify a registry token.

Test the image locally:

```sh
docker build -t mat.bour.io . && docker run --rm -p 8080:80 mat.bour.io
```
